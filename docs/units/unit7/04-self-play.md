## 什么是自博弈(Self-Play)?

要在对抗性游戏中正确地训练智能体可能**相当复杂**。

一方面,我们需要找到一个训练有素的对手来与你的训练智能体对局;另一方面,如果你找到了一个非常强的训练对手,当对手太强时,你的智能体又该如何改进它的策略呢?

想象一个刚开始学踢足球的孩子。让他对抗一名非常优秀的足球运动员毫无用处,因为想要赢球、甚至偶尔抢到球都太难了。于是这个孩子会不断输球,根本没有时间学到好的策略。

最好的办法是**让对手与智能体处于同一水平,并随着智能体自身水平的提升而提升**。因为如果对手太强,我们什么也学不到;如果太弱,我们就会过度学习一些面对更强对手时毫无用处的行为。

这种解决方案被称为*自博弈(self-play)*。在自博弈中,**智能体用它自己(其策略)的历史副本作为对手**。这样,智能体会与一个水平相当的智能体对局(有挑战性但不会太难),从而有机会逐步改进自己的策略,并在变强之后更新它的对手。这是一种"自举"(bootstrap)出对手并逐步提升对手复杂度的方法。

这和人类在竞技中学习的方式是一样的:

- 我们先与水平相近的对手训练;
- 然后从它身上学习,等掌握了一些技能后,再转向更强的对手。

自博弈也是如此:

- 我们**先用自己智能体的副本作为对手**,这样这个对手就处于相近的水平。
- 我们**从它身上学习**,等掌握一些技能后,就**用训练策略的更新副本替换对手**。

自博弈背后的理论并不新鲜。早在五十年代,Arthur Samuel 的跳棋程序就使用过它;1995 年,Gerald Tesauro 的 TD-Gammon 也用到了这一技术。如果你想深入了解自博弈的历史,[可以阅读 Andrew Cohen 的这篇非常好的博文](https://blog.unity.com/technology/training-intelligent-adversaries-using-self-play-with-ml-agents)。

## MLAgents 中的自博弈

自博弈已集成到 MLAgents 库中,由多个超参数管理,我们马上就会学习这些超参数。但正如文档所解释的,核心在于**最终策略的技能水平与泛化性和学习稳定性之间的权衡**。

与一组变化缓慢或一成不变、多样性低的对手训练**会让训练更加稳定。但如果变化太慢,就有过拟合的风险。**

因此我们需要控制:

- **更换对手的频率**,通过 `swap_steps` 和 `team_change` 参数。
- **保存的对手数量**,通过 `window` 参数。`window` 值越大,意味着智能体的对手池将包含更丰富多样的行为,因为它会包含训练早期阶段的策略。
- **与当前自身对局与从对手池中采样的对手对局的概率**,通过 `play_against_latest_model_ratio` 参数。`play_against_latest_model_ratio` 值越大,表示智能体与当前对手对局的频率越高。
- **保存新对手之前的训练步数**,通过 `save_steps` 参数。`save_steps` 值越大,由于策略接受了更多训练,得到的对手集合将覆盖更宽的技能水平和更多样的打法。

要了解这些超参数的更多细节,你一定要[看看文档的这一部分](https://github.com/Unity-Technologies/ml-agents/blob/develop/docs/Training-Configuration-File.md#self-play)。


## 用 ELO 分数评估我们的智能体

### 什么是 ELO 分数?

在对抗性游戏中,跟踪**累积奖励并不总是衡量学习进度的有意义指标:**因为这个指标**只取决于对手的技能水平。**

相反,我们使用 ***Elo 等级分系统***(以 Arpad Elo 的名字命名),它可以在零和博弈中根据给定人群计算出两名玩家之间的**相对技能水平**。

在零和博弈中:一个智能体获胜,另一个智能体落败。它是对这样一种情形的数学表示:每个参与者的效用得失**恰好被其他参与者的效用得失所平衡**。我们之所以称之为零和博弈,是因为效用之和等于零。

Elo 分数(从一个特定分数开始,通常是 1200)起初可能会下降,但在训练过程中应该会逐步上升。

Elo 系统**是从与其他玩家对局的胜负和平局结果中推断出来的。**这意味着玩家的等级分取决于**其对手的等级分以及与其交手取得的战绩。**

Elo 定义了一个 Elo 分数,表示玩家在零和博弈中的相对技能水平。**之所以说是"相对",是因为它取决于对手的表现。**

其核心思想是把玩家的表现**看作一个服从正态分布的随机变量。**

两名玩家之间的等级分差可以作为**比赛结果的预测依据。**如果一名玩家获胜,但其获胜概率本来就很高,那么它只会从对手那里赢得少量分数,因为这表明它远强于对手。

每局比赛结束后:

- 胜者从败者那里**拿走分数。**
- 分数的多少**由两名玩家的等级分差决定(因此是相对的)。**
    - 如果等级分较高的玩家获胜 → 只会从等级分较低的玩家那里拿走少量分数。
    - 如果等级分较低的玩家获胜 → 会从等级分较高的玩家那里拿走大量分数。
    - 如果打成平局 → 等级分较低的玩家从等级分较高的玩家那里获得少量分数。

所以,如果 A 和 B 的等级分分别为 Ra 和 Rb,那么**期望得分**由下式给出:

<img src="https://huggingface.co/datasets/huggingface-deep-rl-course/course-images/resolve/main/en/unit10/elo1.png" alt="ELO Score"/>

然后,在比赛结束时,我们需要更新玩家的实际 Elo 分数。我们采用与玩家超额发挥或发挥失常的程度**成比例的线性调整**。

我们还定义了每局比赛的最大调整分:K 系数(K-factor)。

- 大师级玩家 K=16。
- 较弱玩家 K=32。

### 示例

我们来看一个例子:

玩家 A 的等级分为 2600

玩家 B 的等级分为 2300

- 我们先计算期望得分:

\\(E_{A} = \frac{1}{1+10^{(2300-2600)/400}} = 0.849 \\)

\\(E_{B} = \frac{1}{1+10^{(2600-2300)/400}} = 0.151 \\)

- 如果主办方规定 K=16 且 A 获胜,则新的等级分为:

\\(ELO_A = 2600 + 16*(1-0.849) = 2602 \\)

\\(ELO_B = 2300 + 16*(0-0.151) = 2298 \\)

- 如果主办方规定 K=16 且 B 获胜,则新的等级分为:

\\(ELO_A = 2600 + 16*(0-0.849) = 2586 \\)

\\(ELO_B = 2300 + 16 *(1-0.151) = 2314 \\)


### 优点

使用 ELO 分数有多个优点:

- 分数**总是守恒的**(出现意想不到的结果时会交换更多分数,但总数始终不变)。
- 它是一个**自我修正的系统**:如果一名玩家击败了较弱的玩家,只会赢得很少的分数。
- 它**适用于团队游戏**:我们为每支队伍计算平均值,然后用于 Elo 计算。

### 缺点

- ELO **不考虑团队中每个人的个体贡献**。
- 等级分通缩(rating deflation):**想要长期维持同样的高等级分,需要一直保持高超的技艺**。
- **无法与历史等级分进行比较**。
